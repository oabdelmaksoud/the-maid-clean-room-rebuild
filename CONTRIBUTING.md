# Contributing

Keep the canonical distribution under `skills/the-maid-rebuild/` self-contained. Its instructions, references, templates, and scripts must work when that directory is copied alone. Root documentation and examples support repository users without becoming hidden skill dependencies.

Before changing a record contract, inspect existing examples and negative tests. Version incompatible changes, update the templates, and add a fixture demonstrating the rule. Preserve historical corpus and run identities. Keep validation read-only, offline, bounded, and independent of agent runtime packages.

Contributions must be original or explicitly permitted for the proposed reuse. Describe inspiration and disclose relevant source exposure. Do not submit proprietary product source, copied product assets, credentials, account data, private endpoint captures, or uncertain research material. A source's public availability is not a reuse license.

Assign clear file ownership when collaborating and preserve concurrent edits. Record the current revision, completed checks, unresolved gaps, and next reproducible action at handoff. Have a separate reviewer evaluate changes; authoring is not reviewer approval.

Use the commands in the [README](README.md) to exercise the sample and tests. Add meaningful negative cases for changed trust boundaries and acceptance rules. A validator pass establishes supported record checks only. Host loading, agent decisions, and target outcomes require their own evidence.

For a proposed pull request, describe the concrete behavior changed, source/reuse disclosures, test results and limitations, and any format compatibility change. Publication and external submissions require the repository owner's authorization.
