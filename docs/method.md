# Working method

Start with the exact original user request and lock its target, path/identity, objective and intended runtime. For an explicitly bounded request, start with the selected workflow and its failure boundaries; for a faithful rebuild, inventory every requested surface and feature before handoff. Define which sources and observations are permitted, then capture versioned evidence using original synthetic inputs. Keep documented, observed, reported, and unknown claims distinguishable. Record proposed design separately. Independently authored code does not authorize changing the requested appearance, feature scope, native runtime or file compatibility. Record the user's actual decision before changing that objective.

Use the portable [skill](../skills/behavior-rebuild/SKILL.md) for the complete mode instructions. Its [evidence reference](../skills/behavior-rebuild/references/evidence-levels.md) explains classification; its [handoff reference](../skills/behavior-rebuild/references/handoff-boundaries.md) defines the exposure and review boundary.

Obtain a distinct intent review against the original request, inventory completeness review and source/packet review. Distill approved observations into behavioral contracts. Choose commands and architecture independently, with state, error, cancellation, retry, and persistence semantics. Freeze original fixtures, assertions, and oracles before testing. Retain output artifacts and individual trial results. Evaluate feature breadth separately from dependable real-work outcomes. Use the [fidelity supplement](../skills/behavior-rebuild/references/fidelity.md) for paired target/candidate evidence across behavior, visual, journey, interoperability and platform dimensions. Original-design baselines establish regression only; native and file compatibility claims require execution in those actual contexts. Keep unknowns and authorized deviations in denominators rather than inventing a full-fidelity percentage.

When a case fails, record a reproducible gap, its user impact, owner, and recovery acceptance condition. Prioritize harm and exposure before effort. Preserve the failed evidence and rerun affected cases after repair. A separate reviewer evaluates completion.

## Session continuity

Before resuming, confirm the exact request, target/version/path, locked objective, candidate path and workspace/revision, current status, owned files, accepted packet identity, unresolved source decisions, and ranked gaps. Assign bounded tasks with explicit file ownership and acceptance conditions. At a checkpoint, record changes, actual commands/results, blockers, and the next reproducible action. Concurrent agents must integrate and test the combined result; separate successful task reports do not establish combined correctness.
